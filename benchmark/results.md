# ผลทดสอบ: AI ปกติ vs AI + Skill

## วิธีทดสอบ

- **โปรเจคทดสอบ 2 ชุด** ที่ฝังปัญหาไว้รู้ตำแหน่ง (ดู [`answer-key.md`](answer-key.md)) ไม่มี comment ใบ้ในโค้ด
  - Next.js 15 (App Router + Prisma + NextAuth + Stripe): ปัญหา 13 จุด + โค้ดปลอดภัยที่ "ดูเหมือนผิด" (decoy) 4 จุด
  - ASP.NET Core 8 (Web API + EF Core + JWT): ปัญหา 12 จุด + decoy 4 จุด
- **Prompt เดียวกันทั้งสองฝั่ง** (ภาษาไทยสำหรับ Next.js, อังกฤษสำหรับ .NET) แบบที่ผู้ใช้พิมพ์จริง
- **รันแยกกัน** ด้วย agent อิสระ 4 ตัว (Claude Opus 5.5) แต่ละตัวเห็นเฉพาะโปรเจคของตัวเอง ฝั่ง with-skill เห็น Skill ที่ตัดโฟลเดอร์ `evals/` ออกแล้ว จึงไม่เห็นเฉลย
- **ให้คะแนนแบบ blind** โดย agent ผู้ตรวจอีกตัวที่ได้รายงานสลับชื่อเป็น report-1..4 ไม่รู้ว่าอันไหนมาจากฝั่งไหน ตรวจ 41 assertion (`evals/*/graders/`) และเปิดไฟล์จริงเช็คเลขบรรทัดทุกจุด

## สรุปผลแบบตรงไปตรงมา

**สิ่งที่ Skill ไม่ได้ช่วย:** การจับช่องโหว่ security โมเดลปกติทำได้ดีอยู่แล้ว (23/23 ทั้งสองฝั่ง) และไม่หลง decoy เลย ข้อนี้ไม่ใช่จุดขายของ Skill บนโมเดลระดับนี้

**สิ่งที่ Skill ช่วยจริง:**
1. **จับปัญหา architecture ได้** — ทั้งสอง case ฝั่งปกติเห็น logic ราคาใน handler แต่แนะนำแค่ "ทำเป็น constant" ไม่ได้ชี้ว่าผิด layer ฝั่ง Skill ชี้ทั้งคู่ เพราะ checklist ตั้งคำถามนี้ตรงๆ
2. **รายงานใช้ต่อได้ทันที** — ทุก Critical/High มีโค้ดแก้ และแทบทุก finding มีเลขบรรทัด ฝั่งปกติขาดทั้งสองอย่างในหลายข้อ
3. **กระชับกว่า ~40% โดยจับได้ครบเท่ากัน** — 14 vs 23.5 finding ฝั่งปกติใส่เรื่องเล็กปนเยอะ (เช่น แนะนำ CVE จากความจำที่ต้องไปตรวจเอง) ทำให้คนอ่านต้องคัดเอง

**ต้นทุน:** token +12% และเวลา +26% จากการรัน `detect_stack.py` และรอบ verify

## สิ่งที่แก้หลังทดสอบ

ข้อเดียวที่ฝั่ง Skill ไม่ผ่าน (finding รวมกลุ่มเขียนตำแหน่งว่า "several") เกิดจาก SKILL.md สั่งให้รวม Low ที่ซ้ำกันแต่ไม่ได้บอกว่าต้องคงตำแหน่งไว้ แก้แล้วโดยเพิ่มว่า *ต้องระบุ `file:line` ทุกจุดภายในกลุ่ม* (ยังไม่ได้รันซ้ำหลังแก้)

## ข้อจำกัดของการทดสอบ

- รัน configuration ละ 1 รอบต่อ case ตัวเลขเป็นแนวโน้ม ไม่ใช่ผลทางสถิติ
- โปรเจคทดสอบมีขนาดเล็ก (10–15 ไฟล์) และผู้สร้าง Skill เป็นผู้ออกแบบปัญหาเอง
- รายงานจริงทั้ง 4 ฉบับอยู่ใน [`reports/`](reports/) และดูแบบ interactive ได้ที่ `eval-viewer.html`
